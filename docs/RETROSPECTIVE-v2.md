# 회고 v2 — 조각을 버리고 루프를 조립하기까지

> 2026-08-19 ~ 08-21. v1(훅으로 막는 제약 시스템)을 폐기하고
> v2(마켓의 도구를 역할에 끼우는 품질 루프)를 만든 기록.
>
> 결론부터: **직접 만드는 것보다 엮는 게 어려웠다.** 조각은 마켓에 다 있었다.
> 어려운 건 "언제 · 어떤 순서로 · 무엇을 부를 것인가"였고, 그 배선에서만
> 버그가 여섯 번 나왔다.
>
> v1 이 무너진 과정은 [RETROSPECTIVE.md](./RETROSPECTIVE.md).

---

## 1. 방향 — 조각을 만들지 않는다

v1 의 실패를 복기하니 원인은 훅이 아니라 **혼자 다 만들려던 것**이었다.
마켓을 실사해 보니 리뷰 기준(toss frontend-fundamentals), 규칙 생성기(hookify),
커밋 워크플로(commit-commands), 중복 탐지(jscpd), 죽은 코드(knip)까지
전부 이미 있었고 대체로 우리 것보다 나았다.

없는 것은 하나였다 — **배선.** 그래서 v2 는 도구가 아니라 배선이다.

```
소유하는 것   역할 정의(.fe-harness.json) · 트리거(훅) · 누적과 승격(findings)
안 만드는 것  좋은 코드의 정의 · 리뷰 실행 · 린터 · 커밋 메시지 작성기
```

### 원칙은 두 번 시험당했다

**과잉 적용** — a11y 시맨틱 리뷰는 마켓에 조각이 없다는 걸 확인하고도
"조각을 만들지 않는다" 때문에 미뤘다. 원칙은 *"이미 있는 것을 다시 만들지
않는다"*인데 *"아무것도 만들지 않는다"*로 읽고 있었다.

**예외 뚫기** — 고치면서 이번엔 "우리가 만들되 범위를 제한한다"로 적었다.
범위 제한은 지켜지는지 검증할 방법이 없고, 예외가 하나 생기면 두 번째는 쉽다.

**답은 예외가 아니라 분리였다.** 없는 조각은 **별도 저장소의 독립 플러그인**으로
만들고, 루프는 그것을 남의 것과 똑같이 끼운다. 원칙을 손대지 않고 칸이 채워진다.
위장을 막는 판정 기준도 하나로 족했다 — *"이 루프 없이 단독으로 설치해서
써도 말이 되는가."*

---

## 2. 훅의 방향을 뒤집다 — 문에서 초인종으로

v1 의 훅은 *쓰기 직전에 막는 문*이었다. v2 의 훅은 *커밋 시점에 루프를 깨우는
초인종*이다. **같은 부품, 반대 방향.**

이걸 가능하게 한 발견이 `asyncRewake` 다. 공식 security-guidance 플러그인이
쓰는 훅 옵션으로, `git commit` 을 감지해 **백그라운드에서 돌고 끝나면 모델을
다시 깨워** 결과를 물린다. 사람의 턴을 막지 않으므로 비싼 검사를 넣을 수 있다.

마지막 날 `PreToolUse` 훅이 **하나도 남지 않았다.** v1 의 중심 명제("쓰기 직전
반려가 핵심")가 완전히 뒤집힌 지점이다.

### 분량 게이트 — 작동하는 것을 껐다

분량 차단은 v1 유일한 생존자였다. 실측 p95 에 정확히 앉았고 실사용에서도
잘 돌았다. 그런데 이 게이트를 정당화하던 명제("새 파일은 싸게, 기존 파일은
비싸게")를 v2 가 폐기했다.

> **근거가 철회된 장치를 "작동하니까" 남기는 것이 잡동사니가 쌓이는 방식이다.**

경고로 강등하고, 차단이 사라진 자리는 루프가 채운다 — "파일이 길다"는 신호가
findings 에 3회 쌓이면 루프가 hookify 차단 규칙 승격을 제안한다. **차단할지
말지를 우리가 짐작하지 않고 사용자의 데이터가 정한다.**

## 3. 절차는 한 곳에만 — 훅과 커맨드가 같은 파일을 본다

"커맨드(`/lap`)가 있는데 훅으로 자동화하면 커맨드는 죽은 코드가 되지 않나?"

이 질문이 구조를 정했다. 훅 스크립트에 절차를 넣으면 셸 한 벌과 마크다운
한 벌이 되고, 둘은 반드시 갈린다.

```
훅          방아쇠 + 결정적 계산(jscpd 델타)까지만
              ↓ asyncRewake
rewake      "나머지는 /lap 절차대로" + 계산 결과 첨부
              ↓
모델         lap.md 를 읽고 review · refine · learn 수행
```

**절차의 정의는 lap.md 하나. 진입점만 둘이다** — 사람이 치는 `/lap`, 훅이
깨우는 경로. 이 규칙은 곧바로 값을 했다. 루프 구조를 6단계에서 4단계로 다시
쓸 때 훅은 한 줄도 안 고쳤다.

부수 규칙도 하나 나왔다 — **훅이 검사를 마치고 깨웠으면 모델은 같은 검사를
다시 돌리지 않는다.** 느릴 뿐 아니라, 그 사이 파일이 바뀌면 두 결과가 어긋난다.

## 4. 버그 여섯 — 전부 "배선"에서 나왔다

조각 자체는 검증된 것들이라 조용했다. 터진 곳은 전부 이음새다.

### ① 루프가 커밋을 품고 있었다

설계 문서와 README 는 처음부터 "커밋 후에 돈다"였는데, `lap.md` 만
`verify → review → refine → **커밋** → learn` 이었다. v1 의 `/ship`(배포
파이프라인) 뼈대를 이름만 바꿔 물려받은 탓이다.

문서 불일치로 끝나지 않는다 — **`/lap` 이 커밋하면 커밋 훅이 그걸 감지해
루프가 두 번 돈다.** 커밋·푸시·PR 을 루프 밖으로 빼고 4단계로 줄였다.

### ② 델타 기준이 문서와 달랐다

"README 의 `HEAD` 와 `main...HEAD` 가 무슨 뜻이냐"는 질문에 답하려고 코드를
확인하니, 문서는 `HEAD` 기준인데 스크립트 기본값은 `HEAD~1` 이었다. 커밋
직전에 돌면 **직전 커밋의 중복까지 이번 변경 탓으로 보고**하고 있었다.

> 표기법 질문이 버그를 드러냈다. 문서가 어렵게 읽힌다는 말은
> 종종 문서와 구현이 어긋나 있다는 말이다.

수정 후 기준은 커밋 여부로 자동 판정한다 — `git diff --quiet HEAD && base=HEAD~1 || base=HEAD`.
어느 시점에 불러도 *아직 리뷰 안 된 가장 최근 변경*을 본다.

### ③ jq 의 `//` 가 false 를 삼켰다

`trigger.commit: false` 로 트리거를 껐는데 그대로 돌았다.
`jq -r '.trigger.commit // empty'` 의 `//` 는 `null` 뿐 아니라 **`false` 도
"값 없음"으로** 취급한다. 기존 코드는 `true` 인지만 검사해서 우연히 멀쩡했고,
`false` 를 검사하는 첫 순간에 드러났다.

> **끄려고 적은 설정이 조용히 무시되는 것은 에러보다 나쁘다.**
> 사용자는 껐다고 믿는다.

### ④ 호환 폴백이 검증을 막았다

설정 스키마를 `verify.*` 로 묶으면서 구 스키마 폴백을 모든 getter 에 달았다.
그러다 폐기 버전의 폴백을 영구히 들고 다닐 이유가 없어 지웠더니 —
**테스트 10개가 깨졌다. 전부 구 스키마 설정을 쓰고 있었다.**

폴백이 있는 동안은 새 스키마를 하나도 검증하지 못하고 있었던 것이다.
호환 계층은 회귀를 막는 대신 **검증도 같이 막는다.** 폴백 대신 옛 키를
감지해서 "이제 안 읽는다"고 알리는 쪽으로 바꿨다.

### ⑤ 차단을 지우자 신호에 구멍이 났다

컴포넌트 차단 훅을 지웠는데, 경고 훅이 "Write 는 차단 훅이 이미 반려했으므로
건너뛴다"로 돼 있었다. 차단이 사라지는 순간 **Write 경로의 신호가 통째로
사라질 뻔했다.** 차단을 걷을 때는 그 차단을 전제하던 코드를 같이 봐야 한다.

### ⑥ 안내 문구가 설정을 하드코딩했다

주입 문구를 고치다 컴포넌트 임계값을 `1개`로 박아 넣었다. 설정을 2로 바꿔도
"1개"라고 말한다. 기존 테스트는 "컴포넌트를 언급하지 않는다"는 낡은 단언이라
못 잡았다. 테스트를 **"차단한다고 주장하지 않는다"**는 불변식으로 바꿨다 —
단언은 구현이 아니라 지켜야 할 성질을 적어야 한다.

## 5. 의존성 — 선언한 대로 죽는다

"조각을 만들지 않는 도구가 조각 없이도 조용히 돌면 그건 도는 척이다."
그래서 `dependencies` 로 강제하기로 했고, **정말로 죽는 것을 실측으로 봤다:**

```
claude plugin update fe-harness
  ✘ failed to load
  Error: Dependency "commit-commands@claude-plugins-official" is not installed
```

- hookify 는 자동 설치됐는데 commit-commands 는 안 됐다. 한 번에 다
  해결된다고 가정하면 안 된다
- 로컬 디렉터리 마켓은 `marketplace update` 를 먼저 해야 새 매니페스트를
  읽는다. 안 하면 `already installed` 로 조용히 구 버전이 남는다
- **설계 문서에 "앞으로 만들 플러그인"을 dependencies 에 미리 적어뒀다가
  들켰다.** 매니페스트는 문서가 아니라 실행 대상이다 — 그대로 실행했으면
  플러그인이 통째로 죽었다

필수/선택 기준은 한 번 흔들렸다 — "폴백 품질을 보증할 수 있는가"로 좁혔다가,
그건 사람이 매번 판단해야 해서 결론에 맞춰 기준을 고치는 모양이 됐다.
**"기본 조합이 이름을 부르는 것은 전부 필수"**로 되돌렸다. 두 목록을 diff
하면 검증이 끝나는 기준이 좋은 기준이다.

## 6. 분류 축 하나가 설계 전체를 정했다

```
프로그램이 판정할 수 있다   → verify   타입 · 린트 · 테스트 · 중복 · 죽은 코드
셀 수는 있지만 판단이 필요   → 신호만   파일 길이 · 컴포넌트 개수
읽어야 안다                → review   응집도 · 이름 · 패턴 · 시맨틱
```

v1 은 "셀 수 있는가"로 선을 그었다가 컴포넌트 개수를 차단에 넣는 실수를 했고,
그 반작용으로 **진짜 결정적인 것(중복 · 죽은 코드)까지 판단 영역으로 밀어냈다.**
중복은 셀 수 있고 동시에 틀렸다고 단정할 수 있다 — 에이전트에게 시킬 일이
아니라 jscpd 가 셀 일이다. 정확하고 비용도 낮다.

같은 축이 곳곳에서 재사용됐다:

- **verify-scan** — `0` 과 "못 쟀다"를 구분한다. 섞으면 도구가 죽었을 때
  "중복이 사라졌다"고 보고한다
- **findings** — "같은 종류의 지적 3회"를 자연어로 판단하면 그때그때 달라진다.
  카테고리를 고정해 **필드 일치로 셀 수 있게** 만들어야 루프가 닫힌다
- **setup** — `detect-project.sh` 는 "knip 이 있나" 같은 사실만 내고,
  "scripts.test 를 Stop 게이트에 넣어도 되나" 같은 판단은 사람에게 묻는다.
  이름만 보고 e2e 를 게이트에 넣으면 매 턴이 몇 분씩 늘어난다

## 7. 문서도 거짓말을 한다

"훅의 최악은 차단이 아니라 거짓말"은 v1 의 교훈이었는데, v2 에서 같은 원리가
문서에 적용됐다. README 가 **삭제한 훅의 "반려" 동작과 안 읽는 설정 키를
안내하고 있었다.** 문서가 없는 동작을 설명하는 것은 훅이 없는 문제를 보고하는
것과 같은 실패다.

첨삭 과정에서 확립된 것들:

- **읽는 코드가 없는 설정 키는 쓰지 않는다.** "옵션으로 남겼다"는 기분이 들
  뿐, 아무도 안 켜는 키가 하나 늘 뿐이다
- **README 는 무엇을 하는지, DESIGN 은 왜 그렇게 정했는지.** 저자의 원칙
  선언("~하는 게 낫다")이 사용법 절에 있으면 겉돈다
- **사설 저장소 실측 수치는 공개 문서의 근거가 못 된다.** 수치 대신 정당한
  패턴의 실례(아이콘 배럴, 타입 정의, SVG)로 설득한다
- 문서를 다시 쓰면 **그 문서를 가리키던 코드 주석도 이사해야 한다.**
  훅 주석의 장 번호가 전부 v1 문서 기준으로 남아 있었다

## 부록 — 블로그로 쓸 만한 것

1. **"조각은 다 있었다. 없는 건 배선이었다"** — 마켓 실사로 자작 계획을
   접은 이야기. 버그 여섯이 전부 이음새에서 난 것까지
2. **"훅을 문에서 초인종으로"** — asyncRewake 로 차단 없이 루프를 깨우는 패턴
3. **"절차는 한 곳에만"** — 훅과 커맨드가 같은 마크다운을 바라보게 한 설계.
   자동화가 커맨드를 죽이지 않는 방법
4. **"jq 의 // 는 false 를 삼킨다"** — 끄려고 적은 설정이 조용히 무시된 버그
5. **"호환 폴백이 테스트를 눈멀게 했다"** — 폴백을 지우자 테스트 10개가
   구 스키마였음이 드러난 이야기
6. **"작동하는 게이트를 끄는 결정"** — 근거가 철회된 장치를 남기지 않는 것,
   그리고 그 자리를 사용자 데이터(findings 3회 승격)가 채우게 한 설계
7. **"표기법 질문이 버그를 드러냈다"** — 문서가 안 읽히는 곳에 구현 불일치가
   숨어 있던 이야기
